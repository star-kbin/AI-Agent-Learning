# 03-05. GitHub에 학습 결과 기록하기

[← 목차](./README.md) | [다음 →](./06_integrated_practice.md)

## 목표
GitHub 웹 화면에서 저장소·파일·변경 기록·Pull Request(PR)를 이해합니다. **Git 명령어 설치 없이도 README 수정 실습**을 할 수 있습니다.

## 1. 주요 개념
|용어|의미|
|---|---|
|Repository|프로젝트 파일과 변경 이력을 보관하는 공간|
|Commit|어떤 내용이 왜 바뀌었는지 기록하는 단위|
|Branch|기존 작업과 분리된 변경 흐름|
|Pull Request|다른 변경을 검토하고 반영하도록 요청하는 절차|
|README.md|첫 화면에 표시되는 프로젝트 소개 문서|

## 2. 웹 화면 실습
1. [GitHub](https://github.com/)에 로그인합니다.
2. 연습용 **별도의 새 저장소**를 만들어 공개해도 되는 내용만 넣습니다.
3. **Add file → Create new file**에서 `README.md`를 만듭니다.
4. 목표·파일 구성·실행 방법·확인 기준을 4개 항목으로 작성합니다. 예: “가상 빵가게 3일 기록, 판매 85개·매출 170,000원 검산”.
   - 데이터는 [sample.csv](../examples/bakery_sales/sample.csv)를 사용하고 [열 뜻과 가정](../examples/bakery_sales/README.md)을 README에 함께 적습니다.
5. 'Commit changes'를 눌러 변경 이유를 적고 저장합니다.
6. 저장소 첫 화면으로 돌아가 README 표시를 확인합니다.
7. **History/Commits**에서 변경 이력을 확인합니다.

> GitHub의 메뉴 표시 이름은 화면 개편에 따라 달라질 수 있습니다. 처음 실습은 별도의 연습 저장소에서 수행하세요.

## 3. 팀 협업 선택 과제
작업 브랜치를 생성하고 `README.md`를 수정한 뒤 PR을 작성합니다. **PR을 열었다는 것만으로 main에 반영되지는 않습니다.** diff를 검토하고 승인·병합이 필요한지 확인합니다.

## 4. 보안 규칙
- 비밀번호·API 키·개인정보·기업 내부자료 업로드 금지
- 실수로 유출한 키는 파일을 지우는 것만으로 안전해지지 않으므로 **즉시 폐기·재발급**
- 저작권이나 재배포 권한이 불명확한 자료는 공개 전 확인
- AI가 만든 코드는 내용을 이해하고 테스트한 뒤 commit

## 제출물
README 링크, commit 링크 또는 기록, 변경 이유 2문장, 공개 전 확인한 보안 항목.
