# 04-02. 표 읽기와 데이터 품질 점검

[과정 목차](./README.md) · [저장소 홈](../README.md)

## 목표와 준비

[빵가게 CSV](../examples/bakery_sales/sample.csv)의 한 행이 하루를 뜻한다는 것을 이해하고, 계산 전에 입력 오류를 찾습니다. 파일 업로드 없이 GitHub 표와 계산기로 진행할 수 있습니다.

## 표의 뜻 먼저 확인하기

| 열 | 뜻 | 단위와 확인 기준 |
|---|---|---|
| 날짜 | 판매한 날 | 이 예제는 하루 한 행 |
| 준비수량 | 그날 준비한 빵 | 개, 0 이상의 정수 |
| 주문수량 | 손님이 원한 빵 | 개, 0 이상의 정수 |
| 판매수량 | 실제 판 빵 | 준비와 주문 중 작은 값 |
| 개당가격 | 빵 하나의 가격 | 원/개, 0 이상의 정수 |

이 수업은 재고 이월·할인·반품이 없습니다. 실제 업무의 판매 기록에 이 규칙을 무조건 적용하면 안 됩니다. 실제 규칙을 먼저 물어보세요.

## 오류 찾기 실습

아래는 원본과 별도로 만든 **오류 연습 표**입니다. 값을 자동으로 보충하지 말고 확인할 사항을 적습니다.

| 날짜 | 준비 | 주문 | 판매 | 가격 |
|---|---:|---:|---:|---:|
| 10-01 | 30 | 25 | 25 | 2000 |
| 10-01 | 30 | 25 | 25 | 2000 |
| 10-02 | 40 | 45 | 45 | 2000 |
| 10-03 | 30 | 20 | 빈칸 | 2000 |

1. 원본 3행과 대조해서 중복 날짜를 찾습니다.
2. 준비량을 넘긴 판매를 찾습니다.
3. 빈칸은 0인지 누락인지 알 수 있는지 판단합니다.
4. 원본을 보존하고 별도 정리 표에 수정값과 근거를 기록합니다.

<details>
<summary>확인 정답</summary>

10-01이 중복되었습니다. 원본은 하루 한 행이므로 한 행만 남기되 중복 제거 기록을 남깁니다. 10-02 판매는 원본의 40개로 확인합니다. 10-03 판매는 원본의 20개로 확인합니다. 원본이 없다면 임의 수정 대신 확인 필요로 표시합니다. 빈칸을 0으로 바꾸면 판매량이 과소 집계될 수 있습니다.

</details>

## AI 요청 예시

```text
위 오류 연습 표를 검사해 줘. 원본 표도 함께 제공할게.
출력은 행 / 문제 / 원본 근거 / 수정 제안 표로 해 줘.
입력에 없는 값은 추정하지 말고 원본과 정리본을 구분해.
```

완료 기준: 중복·규칙 위반·누락을 각 1개 이상 찾고, 모든 수정에 근거를 남깁니다. 원본이 없을 때의 처리도 설명합니다.
