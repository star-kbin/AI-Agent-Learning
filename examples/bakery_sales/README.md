# 빵가게 3일 기록으로 배우는 AI 활용

가게를 운영해 본 적이 없어도 읽을 수 있는 **교육용 가상 데이터**입니다. 실제 가게의 판매 실적이나 가격이 아닙니다. 코딩 없이 표와 계산기만으로 시작할 수 있습니다.

[CSV 파일 보기·다운로드](./sample.csv) · [Python 계산 예제](./calculate.py) · [저장소 첫 화면](../../README.md)

## 1. 어떤 상황인가요?

한 종류의 빵을 개당 2,000원에 파는 작은 가게입니다. 매일 빵을 준비하고, 손님이 주문한 만큼 판매합니다. 준비한 수량이 부족하면 일부 주문을 채우지 못합니다.

- 같은 날 준비한 빵만 판매하며, 남은 빵은 다음 날로 이월하지 않는다고 가정합니다.
- 반품·할인·예약 취소·다른 상품 판매는 없습니다.
- 수량은 **빵 개수**입니다. 사람 수나 주문 건수가 아닙니다.
- 비용 자료가 없으므로 매출은 계산해도 **이익은 계산하지 않습니다.**

## 2. 원본 데이터

| 날짜 | 준비 수량(개) | 주문 수량(개) | 판매 수량(개) | 개당 가격(원) |
|---|---:|---:|---:|---:|
| 2026-10-01 | 30 | 25 | 25 | 2,000 |
| 2026-10-02 | 40 | 45 | 40 | 2,000 |
| 2026-10-03 | 30 | 20 | 20 | 2,000 |

CSV는 쉼표로 칸을 구분한 텍스트 파일입니다. [sample.csv](./sample.csv)를 열어 같은 값인지 확인하세요. 스프레드시트에서 한글이 깨지면 데이터를 가져올 때 **UTF-8** 인코딩을 선택합니다.

## 3. 열 이름을 쉬운 말로 읽기

| CSV 열 이름 | 쉬운 뜻 | 단위·예시 |
|---|---|---|
| 날짜 | 어느 날의 기록인지 | 2026-10-01 |
| 준비수량 | 그날 판매할 수 있도록 마련한 빵, 이 예제의 공급량 | 개 |
| 주문수량 | 손님들이 사고 싶다고 요청한 빵, 이 예제에서 기록한 수요 | 개 |
| 판매수량 | 실제로 손님에게 판 빵 | 개 |
| 개당가격 | 빵 한 개의 판매 가격 | 원/개 |

**수요와 판매는 다릅니다.** 10월 2일에는 45개를 요청받았지만 40개만 준비해 40개를 팔았습니다. 판매량만 보면 5개의 추가 요청이 있었다는 사실을 놓칩니다. 기록한 주문 수량도 전체 시장의 수요를 측정한 값은 아닙니다.

## 4. 직접 계산해 보기

| 계산할 것 | 계산 방법 | 첫날의 계산 |
|---|---|---|
| 매출 | 판매 수량 × 개당 가격 | 25개 × 2,000원/개 = 50,000원 |
| 남은 빵 | 준비 수량 - 판매 수량 | 30개 - 25개 = 5개 |
| 못 채운 주문 | 주문 수량 - 판매 수량 | 25개 - 25개 = 0개 |

이 예제에서는 실제 판매 수량이 준비 수량과 주문 수량 중 작은 값과 같습니다. 매출은 판매한 금액이며, 재료비·임대료 등을 뺀 이익이 아닙니다.

### 손계산 정답

| 날짜 | 매출(원) | 남은 빵(개) | 못 채운 주문(개) |
|---|---:|---:|---:|
| 2026-10-01 | 50,000 | 5 | 0 |
| 2026-10-02 | 80,000 | 0 | 5 |
| 2026-10-03 | 40,000 | 10 | 0 |
| **3일 합계** | **170,000** | **15** | **5** |

- 총 판매 수량: **25 + 40 + 20 = 85개**
- 총 매출: **50,000 + 80,000 + 40,000 = 170,000원**
- 하루 평균 판매 수량: **85 ÷ 3 ≈ 28.33개**. 평균이므로 소수로 표시할 수 있습니다.
- 준비 합계 100개 = 판매 85개 + 일별 남은 빵 합계 15개
- 주문 합계 90개 = 판매 85개 + 못 채운 주문 5개

남은 빵 15개는 **각 날짜에 남은 수량의 합계**입니다. 매일 재고를 이월하지 않는 가정이므로 셋째 날 마감 재고 10개와 혼동하지 마세요.

## 5. 복사해서 쓰는 요청문

```text
목표: 빵가게 3일 기록의 판매량·매출·남은 빵·못 채운 주문을 정리해 줘.
맥락: 데이터 분석을 처음 하는 일반 사용자가 볼 설명이야.
입력: 아래 CSV 전체를 붙여 넣을게. 수량은 개, 가격은 원이야.
제약: 교육용 가상값만 사용해. 재고 이월·반품·할인은 없어.
      원가 자료가 없으므로 이익을 계산하거나, 다음 날 수요를 단정하지 마.
출력: 날짜별 계산표, 합계, 쉬운 설명 3문장, 추가로 확인할 정보 2개.
검증: 계산식을 보여 주고, 준비량=판매량+남은 빵과 주문량=판매량+못 채운 주문을 확인해 줘.
      파일이나 코드를 실행하지 않았다면 실행했다고 말하지 마.
```

요청문 아래에 `sample.csv`의 헤더와 3개 행을 모두 붙여 넣거나, 파일 첨부가 가능한 환경에서 파일을 제공합니다. **열 이름만 주는 계획 실습**과 **행 데이터까지 주는 계산 실습**을 구분하세요.

## 6. 코딩 없이 / 코딩으로 진행하기

**코딩 없이:** 표를 읽고 계산기로 3일 합계를 구한 뒤 AI의 표와 대조합니다. 문장 요약과 3장 발표자료를 만들어도 좋습니다.

**Python 선택 실습:** `calculate.py`와 `sample.csv`를 같은 폴더에 저장합니다. Python이 있는 환경에서 그 폴더의 터미널을 열어 실행합니다.

```text
python calculate.py
```

```text
총 판매 수량: 85개
총 매출: 170,000원
일별 남은 빵 합계: 15개
못 채운 주문 수량: 5개
```

03과정처럼 파일을 `data/sample.csv`에 두고 직접 `calculate.py`를 만드는 경우에는 코드의 입력 경로도 그 위치로 맞추세요. 이 폴더의 완성 예제는 **같은 폴더의 CSV**를 읽습니다.

## 7. 더 생각해 볼 문제

1. 주문이 가장 많았던 날과 판매가 가장 많았던 날은 언제인가요?
2. 다음 날 빵을 45개 준비하면 반드시 모두 팔릴까요? 추가로 어떤 기록이 필요할까요?
3. 판매 수량만으로 손님이 원한 빵의 개수를 모두 알 수 있을까요?
4. 가격을 바꾸었을 때 주문이 어떻게 달라질지는 이 3일 기록으로 알 수 있을까요?

<details><summary>해설 보기</summary>

1. 둘 다 10월 2일입니다. 주문 45개, 판매 40개입니다.
2. 보장할 수 없습니다. 더 긴 기간의 날짜별 주문, 휴무·행사·날씨·가격 같은 조건을 함께 확인해야 합니다.
3. 없습니다. 준비 수량이 부족한 날에는 못 채운 요청이 생길 수 있습니다.
4. 알 수 없습니다. 3일 모두 같은 가격이고 다른 조건도 충분히 기록하지 않았습니다.
