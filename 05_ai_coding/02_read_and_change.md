# 05-02. 작은 코드 읽기와 변경

[과정 목차](./README.md) · [저장소 홈](../README.md)

## 목표

짧은 코드를 위에서 아래로 읽고 한 번에 하나의 계산 오류를 고칩니다. 실습은 읽기만 해도 되며 Python 실행은 선택입니다.

## 일부러 틀린 코드

아래 코드는 실행용 정답이 아니라 **오류 찾기 자료**입니다.

```python
prepared = 40       # 준비한 빵
requested = 45      # 손님이 원한 빵
unit_price = 2000   # 하나의 가격
sold = requested   # 여기의 규칙이 맞을까요?
revenue = sold * unit_price
print(revenue)
```

1. `=`는 오른쪽 계산 결과를 왼쪽 이름에 저장합니다.
2. `*`는 곱셈입니다. `print`는 화면에 보여줍니다.
3. 그대로라면 45×2000=90,000을 출력하지만 준비한 빵은 40개뿐입니다.
4. 바꿀 줄은 `sold = min(prepared, requested)`입니다. 바꾼 뒤 예상값은 80,000입니다.

## 함수로 확장하기

[실행 가능한 하루 계산 예제](../examples/bakery_sales/daily_sales.py)를 엽니다. `def`는 함수 정의, `return`은 결과 반환, `raise ValueError`는 잘못된 입력 중단입니다. 중괄호 안의 이름과 값 묶음은 딕셔너리이며 결과를 이름으로 찾을 때 씁니다.

기본 읽기 순서: 입력 검사 → 판매 계산 → 결과 반환. 처음부터 모든 문법을 외울 필요는 없습니다. `calculate_day(40, 45, 2000)`의 각 숫자가 무엇인지 설명해 보세요.

## AI와 변경을 검토하기

```text
이 코드에서 주문이 준비보다 많을 때 생기는 오류를 설명해 줘.
먼저 40,45,2000을 손으로 추적한 뒤 계산 줄 하나의 수정안을 보여 줘.
수정 이유와 30,25,2000 사례가 계속 맞는지도 설명해 줘.
```

완료 기준: 수정 전 90,000과 수정 후 80,000의 이유를 설명하고, 다른 정상 사례 50,000도 확인합니다. AI가 코드를 길게 다시 써도 실제로 바뀌어야 하는 규칙을 먼저 찾습니다.
