# 05-03. 테스트와 오류 수정

[과정 목차](./README.md) · [저장소 홈](../README.md)

## 목표

정상·경계·잘못된 입력을 나눠 검사하고, 오류를 재현한 뒤 수정합니다. 테스트는 “같은 입력에서 약속한 결과가 나오는지 확인하는 절차”입니다.

## GitHub에서 먼저 풀기

| 사례 | 입력: 준비, 주문, 가격 | 기대 결과와 이유 |
|---|---|---|
| 정상 | 30,25,2000 | 판매25, 매출50000, 남음5, 미충족0 |
| 공급 부족 | 40,45,2000 | 판매40, 매출80000, 남음0, 미충족5 |
| 경계 | 0,5,2000 | 판매0, 매출0, 남음0, 미충족5 |
| 같은 수량 | 5,5,2000 | 판매5, 남음0, 미충족0 |
| 무료 | 5,2,0 | 판매2, 매출0: 이 계약은 가격0 허용 |
| 오류 | -1,5,2000 | ValueError |
| 형식 오류 | 3.5,5,2000 또는 "3",5,2000 | ValueError |

기대값을 구현 코드에서 복사하면 같은 오류를 놓칩니다. 손계산 표를 독립적인 기준으로 사용하세요.

## 선택 실행

Python 3가 준비되었다면 저장소 루트 폴더의 터미널에서 실행합니다. 외부 패키지 설치는 없습니다.

```text
python -m unittest discover -s examples/bakery_sales -p "test_daily_sales.py" -v
```

[테스트 파일](../examples/bakery_sales/test_daily_sales.py)은 정상·0·동일 수량·자료형·음수와 수량 보존을 확인합니다. 종료 상태가 성공이고 `OK`가 나왔는지 확인하세요. 실행하지 않았다면 “예상 결과만 검토함”이라고 적습니다.

## 실패를 다루는 순서

1. 실제 입력과 오류 메시지를 그대로 기록합니다.
2. 기대값을 원문 규칙으로 다시 확인합니다.
3. 가장 작은 실패 사례 하나를 남깁니다: 준비40, 주문45.
4. 판매 계산을 고치고 실패 사례와 기존 정상 사례를 모두 다시 확인합니다.
5. 코드만 고쳐 통과시키지 말고 테스트 기대값도 타당한지 검토합니다.

`python`을 찾지 못하면 코드 오류가 아니라 실행 환경 문제입니다. 설치는 [03 도구 활용](../03_tools/03_vscode_setup.md)을 참고하거나 표 검증 경로로 계속 학습하세요.

완료 기준: 세 유형의 사례와 예상값을 직접 작성하고, 실행했다면 명령·실제 결과·실패 수정 내역을 남깁니다.
