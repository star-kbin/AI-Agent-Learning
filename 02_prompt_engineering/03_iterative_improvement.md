# 02-03. 프롬프트 단계별 개선과 검증

[← 목차](./README.md) · [다음: 실무 예제 →](./04_workplace_examples.md)

## 학습 목표 (30~40분)
동일한 문제를 여러 번 요청하여 프롬프트 수정 효과를 평가합니다.

## 1. 개선 프로세스
```text
문제 정의 → 최초 요청 → 결과 관찰 → 부족한 점 기록
         → 프롬프트 한 요소 수정 → 다시 실행 → 전후 비교
```

## 2. 사례: 실습 과제 안내문
**버전 A**
```text
데이터 분석 과제 만들어 줘.
```

**버전 B**
```text
파이썬을 처음 배운 대학생에게 CSV 데이터 분석 실습을 내려고 해.
30분 안에 끝낼 수 있는 과제 3개를 작성해 줘.
입력 데이터의 열 이름은 date, temperature, defect_count야.
각 과제마다 목표, 수행 단계, 제출 결과와 채점 기준을 제시해 줘.
실제 데이터 값이 없으므로 분석 결과 수치는 만들어내지 마.
```

**버전 C (평가 기준 강화)**
```text
위 조건을 유지하면서 각 과제마다 다음 항목을 추가해 줘.
- 합격 기준 2개
- 흔한 실수 1개
- 스스로 확인할 질문 1개
모든 과제의 난이도는 기초 수준으로 유지해 줘.
```

## 3. 결과 비교 기록
|평가 항목|확인 방법|
|---|---|
|요구사항 충족|요청한 항목이 모두 포함되었나?|
|정확성|입력되지 않은 값을 지어내지 않았나?|
|실행 가능성|학습자가 실제로 따라 할 수 있나?|
|형식 준수|분량·표·목차·항목 수를 지켰나?|
|안전성|민감정보 노출이나 위험한 지시가 없나?|

## 4. 평가의 공정성
조건 비교를 할 때는 같은 모델·동일한 원자료를 사용하고 요청 문장 중 변경된 요소를 기록합니다. AI 응답은 매번 달라질 수 있으므로 한 번의 성공만으로 '항상 더 좋다'고 단정하지 않습니다.

**프롬프트 개선 기록 양식**
```text
문제:
초기 프롬프트:
초기 결과에서 부족했던 점:
변경한 요소 (목표/맥락/제약/출력/검증):
개선된 프롬프트:
결과 차이:
남은 오류:
```

## 실습
버전 A와 B를 각각 입력하고 위 표로 비교해 보세요. B에도 부족한 점이 보이면 C를 사용해 개선합니다.

## 추가 팁
- 복잡한 업무는 개요 → 세부 작업 → 검토 단계로 나눕니다.
- 필요하면 **짧은 예시 출력**을 제공해 형식을 보여 줍니다.
- 모델의 '내부 생각 전체'를 요청하기보다 **결론·근거·계산·검증 결과**를 요청합니다.
- 자료가 모자라면 추정하게 두지 말고 질문하거나 '정보 부족'이라고 표시하도록 합니다.
