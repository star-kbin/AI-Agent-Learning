# 02-04. 업무별 프롬프트 실전 예제

[← 목차](./README.md) · [다음: 최종 실습·평가 →](./05_practice_and_assessment.md)

## 학습 목표 (40~60분)
다음 4가지 업무 중 **두 가지를 골라** 프롬프트를 직접 수정하고 결과를 검증합니다.

공통 자료: [빵가게 3일 가상 기록](../examples/bakery_sales/README.md). 수량은 개, 가격과 매출은 원입니다.

## 사례 A — 판매 요약문
```text
너는 동네 가게의 기록 정리를 돕는 조력자야.
[목표] 3일간의 빵 판매 요약문 초안을 작성해 줘.
[입력] 교육용 가상값: 10월 1일 25개, 2일 40개, 3일 20개 판매. 개당 2,000원.
[출력] 판매 현황, 날짜별 비교, 추가 확인 사항의 3개 소제목으로 나눠 줘.
[제약] 제공한 자료 외 성과를 만들어내지 마. 과도한 홍보 표현 금지.
[검증] '확인된 사실'과 '제안'을 구분해 표시해 줘.
```

## 사례 B — 발표자료 기획
```text
[목표] 일반 사용자 대상 '주문 수량과 판매 수량은 왜 다를까?' 발표 목차 작성
[맥락] 가게 운영 경험이 없는 사람 대상 10분 발표
[입력] 가상의 하루 기록: 빵 40개 준비, 손님이 45개 주문, 실제 40개 판매
[제약] 5개 주문을 채우지 못했다는 사실과 그 원인에 관한 추가 추측을 구분할 것
[출력] 6장 슬라이드별 제목, 핵심 메시지, 추천 그림 설명
[검증] 주문 45개 - 판매 40개 = 못 채운 주문 5개인지 확인
```

## 사례 C — 데이터 분석 계획
```text
[목표] 빵가게 준비 수량·주문 수량·판매 수량을 비교할 계획 수립
[입력] 열: 날짜, 준비수량, 주문수량, 판매수량, 개당가격 / 행 데이터는 아직 없음
[맥락] 수요와 판매량의 차이를 처음 배우는 일반 사용자
[제약] 실제 합계나 다음 날 주문 수량을 만들어내지 마
[출력] 열 뜻 확인 → 빠진 값 → 음수·판매 가능 수량 확인 → 표·그래프 → 결과 정리 체크리스트
[검증] 각 단계에서 확인할 지표와 예상 위험을 알려 줘
```

## 사례 D — 코딩 도움 (코딩 경험 없어도 가능)
```text
[목표] CSV의 빵 판매량과 매출 합계를 계산하는 파이썬 예제를 설명해 줘.
[맥락] 파이썬을 처음 배우는 일반 사용자
[입력] 열 이름: 날짜, 준비수량, 주문수량, 판매수량, 개당가격 / 실제 행 데이터는 미제공
[제약] 예제 데이터는 가상 데이터라고 명시하고, 파일이 없으면 실행 불가한 점을 설명
[출력] 주석 있는 코드, 줄별 설명, 실행 전에 확인할 사항, 예상 출력
[검증] 코드 실행을 수행하지 않았다면 '실행 미검증' 표시
```

## 결과 검증 방법
|영역|반드시 직접 확인할 것|
|---|---|
|보고서|원본 판매 수량·가격·계산식 대조|
|발표자료|주문과 판매의 차이·단위·그림 설명의 정확성|
|데이터|데이터 존재 여부, 입력 열·단위, 분석 방법의 적합성|
|코드|실행 환경, 패키지, 오류 처리, 실제 실행 결과|

> 개인 정보·회사 기밀·API 키를 AI 서비스에 무단 입력하지 마세요. 외부 자료를 그대로 지시문으로 믿는 프롬프트 인젝션에도 주의하세요.

## 실습 제출물
선택한 업무마다 **최초 요청 / 수정한 요청 / AI 결과 요약 / 검증한 내용 2개 / 개선할 점 1개**를 기록합니다.
