# 02-02. 좋은 프롬프트의 6요소

[← 목차](./README.md) · [다음: 단계별 개선 →](./03_iterative_improvement.md)

## 학습 목표 (30~40분)
누구나 재사용할 수 있는 **6요소 프롬프트**를 작성합니다.

|요소|확인 질문|예시|
|---|---|---|
|① 목표(Task)|무엇을 완료할까?|3일 빵 판매량과 매출 정리|
|② 맥락(Context)|누가·왜 사용하나?|동네 가게 운영자, 남는 빵을 줄이려는 상황|
|③ 입력(Input)|어떤 자료가 있나?|날짜별 준비·주문·판매 수량과 가격|
|④ 제약(Constraints)|무엇을 지켜야 하나?|수량·가격을 지어내지 않기, 개인정보 제외|
|⑤ 출력(Output)|어떤 형태가 필요한가?|표: 날짜/판매 수량/매출/남은 수량|
|⑥ 검증(Verification)|좋은 결과인지 어떻게 알까?|원자료 근거, 누락·추정 표시|

모든 상황에 요소를 억지로 넣을 필요는 없습니다. **작업에 중요한 요소부터** 정합니다.

## 복사해 쓰는 기본 템플릿
```text
[목표] 수행할 작업:
[맥락] 대상 사용자 / 목적 / 활용 상황:
[입력] 사용할 자료: (실제 자료 입력)
[제약] 분량, 금지사항, 사용 기준, 불확실한 경우 처리:
[출력] 순서, 형식, 필수 항목:
[검증] 수치/근거/누락 검사, 확인 불가능한 내용 표시:
```

## 예시: 빵가게의 판매와 재고 정리
```text
[목표] 3일 동안 판 빵과 남은 빵을 정리해 줘.
[맥락] 일반 사용자가 수량과 판매 금액의 뜻을 이해하려고 해.
[입력] 준비/주문/판매: 10월 1일 30/25/25개, 2일 40/45/40개, 3일 30/20/20개. 개당 2,000원.
[제약] 교육용 가상값만 사용해. 재고 이월·반품·할인은 없고, 비용 자료가 없으므로 이익은 계산하지 마.
[출력] 날짜별 판매 수량/매출/남은 수량/못 채운 주문 수량 표.
[검증] 판매 85개, 매출 170,000원, 남은 빵 15개, 못 채운 주문 5개를 계산식으로 확인해 줘.
```

## 예시: 데이터 요약
```text
[목표] 아래 표의 데이터를 요약해 줘.
[맥락] 실습 발표를 위한 설명이며 통계 초보자가 대상이야.
[입력] 일별 빵 판매 수량: 10월 1일 25개, 2일 40개, 3일 20개
[제약] 주어진 숫자로만 계산하고, 원인을 추정해서 단정하지 마.
[출력] 3문장 요약, 날짜별 표, 추가로 확인할 데이터 2개.
[검증] 총합 85개·하루 평균 약 28.33개의 계산식을 함께 제시해 줘.
```

## 실습
위 템플릿을 이용해 **'빵가게 3일 판매 현황 발표자료 초안'**을 지시해 보세요. 결과에서 실제로 제공되지 않은 사실이 들어갔는지 확인합니다.

## 체크리스트
- [ ] 내가 원하는 최종 결과가 분명하다.
- [ ] 대상과 배경정보가 충분하다.
- [ ] 자료와 추정을 구분한다.
- [ ] 출력 형식을 지정했다.
- [ ] 원자료와 결과를 대조할 기준을 마련했다.
